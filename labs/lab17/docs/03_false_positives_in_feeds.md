# False positives in threat intelligence feeds

A false positive is an indicator that is flagged as malicious although it is benign. False positives are expensive: analysts waste time on alerts, users are blocked from legitimate services and trust in the security team falls. Typical causes are shared infrastructure, sinkholes and research scanners. Public DNS resolvers such as 8.8.8.8 and 1.1.1.1, content delivery networks, and popular domains such as google.com or microsoft.com often appear in malware traffic simply because malware also uses the internet, not because these services are hostile.

Several techniques reduce false positives. Allowlists of known-good infrastructure remove the most common benign indicators before they reach detection tools. Corroboration counts how many independent sources report the same indicator; an indicator seen by only one low-reputation feed deserves less trust than one confirmed by several. Source reputation tracks how often a feed has been right in the past. Decay lowers the score of indicators that have not been observed recently. Finally, enrichment adds context such as the autonomous system, the country and passive DNS history, which helps an analyst see that an address belongs to a large cloud provider. Graph analysis is useful here: feeds that repeatedly share the same benign indicators form suspicious clusters that point to low-quality sources.
