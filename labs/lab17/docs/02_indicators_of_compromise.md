# Indicators of compromise and their limits

Indicators of compromise, or IOCs, are observable artefacts that suggest a system has been attacked. Common types are IP addresses, domain names, URLs, file hashes such as SHA-256, email addresses and registry keys. Security teams load IOCs into firewalls, intrusion detection systems and SIEM platforms so that matching traffic or files raise an alert. The Pyramid of Pain explains why IOCs alone are not enough: hash values and IP addresses are trivial for an attacker to change, domain names are slightly harder, while network artefacts, tools and finally tactics, techniques and procedures are the most painful for an adversary to replace.

IOCs also age quickly. A command and control server may move to a new address within hours, and a cloud IP address that hosted malware yesterday may belong to an innocent customer today. For this reason every indicator should carry a first seen and last seen time, a confidence score and the source that reported it, and old indicators should expire automatically. Sharing standards such as STIX describe indicators in a structured format, and TAXII transports them between organisations. Platforms like MISP let communities exchange IOCs together with the context that explains why an indicator is considered malicious.
