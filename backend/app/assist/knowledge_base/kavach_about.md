# About Kavach and Kavach Assist
## What is Kavach
Kavach is a cyber threat intelligence platform built on MongoDB for the course 23CSE528. It collects real threat data - the CISA Known Exploited Vulnerabilities catalog, GCVE vulnerability sightings, IP blocklists and security news - classifies it, and lets an analyst look up an IP address, a CVE or a report. Labs 7 to 18 each added one database capability to it.
## What is Kavach Assist and how does it answer
Kavach Assist is the chat application of the final assessment. For every question it (1) reads the conversation memory from MongoDB, (2) works out the platform (Linux, Windows, macOS, Android, iOS and others) and threat status you mean, (3) runs exact MongoDB queries on the threat catalog, (4) runs $vectorSearch over the knowledge base for the most relevant passages, and (5) gives all of that to a local language model (Ollama) which writes the answer. Facts such as CVE ids, dates and counts come from MongoDB, not from the model. If no model is running, a built-in writer produces the answer from the same data.
## What do Active, Evolving, Anticipated and Resolved mean
Active: exploitation is confirmed and happening now (listed in a known-exploited catalog or with exploitation sightings). Evolving: the threat is changing - a public proof-of-concept exists, sightings are rising or a new variant appeared - but exploitation is not confirmed. Anticipated: not exploited yet but severe or widely discussed, so attacks are expected. Resolved: a fix exists, the deadline has passed and nothing was sighted in the last 30 days, or the campaign was taken down. Each threat stores the reason for its status.
## What is the scanner bot
The scanner bot is a background service. Every few minutes it scans a project folder and the Linux system it runs on: dependencies with known vulnerabilities (requirements.txt, package.json, checked against OSV.dev and Kavach's exploited list), hard-coded secrets, unsafe file permissions, risky Docker and debug settings, and pending operating-system security updates. It reports findings in the chat. It never changes anything by itself: you ask it to fix, it shows the exact changes, and only after you reply yes does it apply them, keeping a backup so "undo last fix" restores the files.
## Who can sign in and what can the administrator do
There is one administrator account. Everyone else signs in with a Google account or creates an account with email and password. The administrator can see and manage users (disable, approve, reset password, delete), usage and latency metrics, the knowledge base, the scanner bot and the audit log. Passwords are stored as salted scrypt hashes; sessions are signed tokens in an HttpOnly cookie.
## Which MongoDB collections does Kavach Assist use
Database kavach_assist: users, conversations, messages (the conversation memory), threats (the catalog with platform and status), knowledge (text chunks with embeddings and a vectorSearch index), metrics, rate_limits (TTL), audit, scan_findings, scan_jobs, scan_runs and notifications. Threat data is read from database cti_platform.
