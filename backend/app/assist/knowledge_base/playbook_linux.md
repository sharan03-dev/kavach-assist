# Linux mitigation playbook
## Linux: apply security updates (patching)
Most Linux threats are closed by installing the fixed package. Debian / Ubuntu: `sudo apt update && sudo apt upgrade -y` (only security fixes: `sudo unattended-upgrade -d`). RHEL / Fedora / CentOS: `sudo dnf upgrade --security -y`. SUSE: `sudo zypper patch --category security`. Check one package: `apt list --upgradable | grep <name>` or `rpm -q --changelog <name> | grep CVE-XXXX`. After a kernel, glibc or OpenSSL update reboot or restart the services that use them (`sudo needrestart` or `sudo systemctl restart <service>`). Turn on automatic security updates: `sudo dpkg-reconfigure -plow unattended-upgrades` or `sudo systemctl enable --now dnf-automatic.timer`.
## Linux: kernel and privilege-escalation vulnerabilities
For a local privilege-escalation bug (kernel, sudo, polkit, glibc): 1) update the package and reboot into the new kernel (`uname -r` shows the running one). 2) Until you can patch, limit who can log in, remove unneeded SUID binaries (`find / -perm -4000 -type f 2>/dev/null`), and disable unprivileged user namespaces if the advisory says so (`sudo sysctl -w kernel.unprivileged_userns_clone=0`). 3) Review `sudo -l` and `/etc/sudoers.d`. 4) Look for abuse: new users in `/etc/passwd`, unknown SUID files, unexpected entries in `~/.ssh/authorized_keys`, cron jobs and systemd units.
## Linux: remote services such as SSH, web servers and Samba
For a remotely exploitable service: 1) patch it. 2) If no patch exists, block or restrict the port with the firewall: `sudo ufw deny <port>` or allow only trusted networks `sudo ufw allow from 10.0.0.0/8 to any port 22`. 3) SSH hardening in `/etc/ssh/sshd_config`: `PermitRootLogin no`, `PasswordAuthentication no` (keys only), then `sudo systemctl restart sshd`; add fail2ban against brute force. 4) Stop services you do not use: `sudo systemctl disable --now <service>`. 5) Check exposure with `ss -tulpn`.
## Linux: detect and contain a compromise
Signs: unknown processes (`ps auxf`), outbound connections (`ss -tnp`), new cron jobs (`crontab -l`, `/etc/cron.*`), new systemd units, modified binaries (`debsums -c` or `rpm -Va`), logins in `last` and `/var/log/auth.log`. Contain: isolate the host from the network (do not power it off, memory holds evidence), disable stolen accounts, rotate SSH keys and passwords from a clean machine, block the attacker's IPs and domains. Recover: rebuild from a trusted image, restore data from a backup taken before the incident, patch the entry point first, then reconnect.
## Linux: hardening baseline
Keep the system minimal and updated; enable the firewall (`sudo ufw enable`); use SSH keys with MFA for admins; keep SELinux or AppArmor in enforcing mode; run services as non-root users; set `umask 027`; make secrets files mode 600; enable auditd for login and privilege changes; back up important data offline and test the restore; subscribe to your distribution's security announcements.
